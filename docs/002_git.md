## Objetivo

Que el historial del repositorio `gestion-obras-laravel` cuente cómo se construyó la aplicación: una rama por apartado, commits pequeños con mensajes claros, una pull request por apartado y un tag al cerrar cada bloque.

## Flujo de trabajo

```
main ──●──────────●──────────●───────── (siempre en verde)
        \        /  \        /
 RA5_3   ●──●──●     \      /
                      RA5_4 ●──●──●
```

| Elemento | Convención |
|:--|:--|
| Rama | Una por apartado, con su número: `RA5_3`, `RA6_2`, `RA7_4`… |
| Commit | `tipo: descripción en imperativo` (ver tabla siguiente) |
| Pull request | De la rama a `main`, con el resultado de los tests en la descripción |
| Tag | Al terminar un bloque: `bloque-5`, `bloque-6`… |

### Tipos de commit

| Tipo | Uso | Ejemplo |
|:--|:--|:--|
| `feat` | Funcionalidad nueva | `feat: listado de clientes con Blade` |
| `fix` | Corrección | `fix: el NIF vacío no debe chocar con el índice único` |
| `test` | Añadir o cambiar tests | `test: añade RA5_3_RutasTest` |
| `refactor` | Cambio interno sin cambiar el comportamiento | `refactor: extrae ObraService` |
| `docs` | Documentación | `docs: describe la API en openapi.json` |
| `chore` | Configuración, dependencias | `chore: instala laravel/breeze` |

## Ciclo de un apartado

```bash
git switch main && git pull
git switch -c RA5_3

# … ejercicios …
cp /var/www/curso-laravel/docs/materiales/tests/bloque5/RA5_3_RutasTest.php tests/Feature/
php artisan test --filter=RA5_3
git add -A && git commit -m "feat: rutas de clientes y obras"

git push -u origin RA5_3
gh pr create --fill --base main      # o desde la web de GitHub
gh pr merge --merge --delete-branch  # tras revisar el diff y ver la CI en verde
git switch main && git pull
```

Al cerrar un bloque:

```bash
git tag -a bloque-5 -m "Bloque 5: introducción a Laravel" && git push --tags
```

{: .consejo }
Revisar el diff de la pull request antes de fusionar ayuda a detectar ficheros que no deberían subirse (`.env`, `vendor/`, `database/database.sqlite`). El `.gitignore` del esqueleto de Laravel ya los excluye.

## Ejercicios

1. Configurar la identidad de Git dentro del `workspace` (`git config --global user.name` y `user.email`).
2. Añadir la clave SSH del equipo a GitHub y comprobar `ssh -T git@github.com`.
3. Instalar la CLI de GitHub (`gh`) y autenticarse con `gh auth login` (opcional, también se puede trabajar desde la web).
4. Proteger la rama `main` del repositorio de la aplicación: *Settings* → *Branches* → exigir pull request y que pase la CI.
